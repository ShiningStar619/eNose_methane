## 6.1 กรอบวิธีวิจัยโดยรวม

งานวิจัยนี้เป็นงานพัฒนาและตรวจสอบระบบวัดเชิงปริมาณ โดยมีเป้าหมายหลักคือประมาณค่าความเข้มข้นก๊าซมีเทน (CH₄) เป็นหน่วย **ppm** จากสัญญาณจมูกอิเล็กทรอนิกส์ (eNose) ร่วมกับตัวแปรสภาพแวดล้อม แล้วเปรียบเทียบกับค่าอ้างอิงจากก๊าซโครมาโทกราฟีชนิด flame ionization detector (GC-FID) ภายใต้ขอบเขตการศึกษา

ลำดับงานหลักมีสี่ขั้นที่ต่อเนื่องกัน:

1. **สร้างและปรับระบบ eNose** บน Raspberry Pi ให้ควบคุมการไหลของก๊าซ บันทึกสัญญาณเซ็นเซอร์ และแสดงค่าประมาณ ppm ได้  
2. **เก็บชุดข้อมูลที่มีป้ายกำกับ** ในห้องควบคุมความเข้มข้น CH₄ โดยวัดคู่ขนานกับ GC-FID  
3. **สกัดลักษณะเด่นและฝึกแบบจำลองถดถอย** นอกเครื่อง (บนคอมพิวเตอร์วิเคราะห์) แล้วโหลดโมเดลกลับขึ้น Raspberry Pi  
4. **ประเมินความสอดคล้อง** ของค่าที่ทำนายกับค่าอ้างอิงด้วยตัวชี้วัดความคลาดเคลื่อน และระบุข้อจำกัดของระบบ

ค่าที่ระบบประมาณโดยตรงคือความเข้มข้น (ppm) ไม่ใช่ฟลักซ์ (mg m⁻² h⁻¹) การเชื่อมต่อไปสู่ฟลักซ์ต้องอาศัยพารามิเตอร์ chamber และสมมติฐานการสะสมก๊าซแยกต่างหาก ซึ่งอยู่นอกขอบเขตหลักของวิทยานิพนธ์นี้ [6], [21]

```text
เตรียมฮาร์ดแวร์–ซอฟต์แวร์ eNose
        ↓
ทดลองควบคุม: ความเข้มข้น CH₄ × อุณหภูมิฮีตเตอร์
        ↓  คู่ข้อมูล eNose ↔ GC-FID
สกัด ΔV / slope / T·H·P → ฝึก Linear Regression
        ↓
โหลดโมเดลขึ้น Raspberry Pi → ทำนาย ppm ต่อรอบวัด
        ↓
ประเมิน RMSE / MAE / R² บนชุดทดสอบ
```

## 6.2 เครื่องมือและวัสดุ

### 6.2.1 ระบบ eNose ของโครงการ

ชุดเครื่องมือหลักประกอบด้วยหน่วยประมวลผลและเซ็นเซอร์ดังนี้

| องค์ประกอบ | รายละเอียดที่ใช้ในงาน |
|------------|------------------------|
| ตัวควบคุม | Raspberry Pi (ชุดทดลองอ้างอิง Raspberry Pi 5 ตามคู่มือผู้ใช้) |
| ADC ก๊าซ | ADS1263 (SPI) อ่านสัญญาณแรงดันจากเซ็นเซอร์ MOS |
| เซ็นเซอร์ก๊าซ | Figaro **TGS2612** จำนวน 4 ช่อง (มีและไม่มีตัวกรองอย่างละ 2) |
| สภาพแวดล้อม | **BME280** (I2C) อุณหภูมิ ความชื้นสัมพัทธ์ ความดันบรรยากาศ |
| การไหลของก๊าซ | วาล์วโซลินอยด์ ปั๊ม พัดลม ควบคุมผ่านรีเลย์ |
| ฮีตเตอร์ | รักษาอุณหภูมิเซ็นเซอร์ตามค่าที่ตั้งในช่วงทดลอง |
| ซอฟต์แวร์ | โปรแกรมควบคุม GUI บน Raspberry Pi บันทึกข้อมูลดิบและประมวลผลเป็น CSV |

หมายเหตุสเปก: บทนี้ยึดคู่มือระบบและท่อทำนายในคลังโค้ดที่ใช้ **TGS2612** เป็นหลัก เอกสารร่างเก่าบางฉบับที่กล่าว TGS2611/MQ4 ไม่ใช้เป็นสเปกของวิธีวิจัยนี้

### 6.2.2 วิธีอ้างอิงและวัสดุสอบเทียบ

| รายการ | บทบาท |
|--------|--------|
| GC-FID | ให้ค่าความเข้มข้น CH₄ อ้างอิง (ground truth) สำหรับฝึกและตรวจสอบแบบจำลอง [6], [7] |
| มาตรฐานก๊าซ CH₄ / ระบบเจือจาง | ตั้งความเข้มข้นเป้าหมายในห้องหรือท่อทดสอบตามระดับที่กำหนดใน §6.3 |
| ห้อง/ท่อทดสอบควบคุม | ควบคุมความเข้มข้นและลดการรบกวนจากลมภายนอกระหว่างรอบวัด |

รายละเอียดยี่ห้อ/รุ่น GC-FID และปริมาตรระบบทดสอบให้ระบุเมื่อยืนยันจากบันทึกทดลองจริง (**TBD**)

### 6.2.3 ซอฟต์แวร์วิเคราะห์

- การเก็บและควบคุมลำดับวัด: โปรแกรม eNose บน Raspberry Pi  
- การสกัดลักษณะเด่นและทำนายบนเครื่อง: `predict_methane.py` โหลดโมเดลจาก `models/methane_linreg_model.joblib`  
- การฝึกโมเดลและการตรวจสอบไขว้: สคริปต์วิเคราะห์นอก Raspberry Pi (ชุด BuildML) โดยใช้การแบ่งกลุ่มรอบวัดเพื่อลดการรั่วไหลของข้อมูลระหว่างพับ

## 6.3 ขอบเขตการทดลอง

ขอบเขตหลักตามแบบเสนอและโครงร่างปัจจุบันมีดังนี้

| มิติ | ขอบเขตที่ใช้ในการเก็บข้อมูลฝึก/ทดสอบ |
|------|----------------------------------------|
| ความเข้มข้น CH₄ เป้าหมาย | 5, 10, 15, 20, 30, 40, 50, 60, 70, 80, 90, 100 ppm |
| อุณหภูมิฮีตเตอร์ (จุดตั้ง) | 30, 40, 50 °C |
| ปริมาณที่ประมาณ | ความเข้มข้น CH₄ (ppm) จาก eNose–ML |
| วิธีอ้างอิง | GC-FID ภายใต้เงื่อนไขสุ่มตัวอย่างที่กำหนดคู่กับรอบวัด |
| สภาพแวดล้อมหลักของชุดข้อมูล | การทดลองควบคุมในห้อง/ท่อทดสอบ (ยังไม่ใช่การติดตามตลอดฤดูปลูกในแปลงนาเป็นชุดฝึกหลัก) |

ข้อจำกัดที่ต้องระบุชัดเมื่อรายงานผล:

1. ค่า ppm จากโมเดลเป็น**ค่าประมาณจากการสอบเทียบ ML** ไม่ใช่ค่ามาตรฐานรับรองทางมาตรวิทยาแทน GC  
2. ช่วงความเข้มข้นและอุณหภูมิที่อยู่นอกตารางฝึกไม่ควรถูกตีความว่ามีความแม่นยำเท่าช่วงที่ฝึก  
3. การนำไปใช้ในนาจริงต้องเผชิญความชื้นสูง ลม และองค์ประกอบก๊าซรบกวนเพิ่มเติม ซึ่งอยู่นอกขอบเขตการยืนยันหลักของชุดข้อมูลควบคุม

## 6.4 โปรโตคอลการวัดด้วยระบบ eNose

### 6.4.1 ลำดับอัตโนมัติ (Auto sequence)

แต่ละรอบวัดใช้โหมด Auto ตามลำดับ Op1–Op7 ดังนี้ (ค่าเวลาเริ่มต้นตามคู่มือ; ปรับได้ใน Settings แต่ต้องบันทึกค่าที่ใช้จริงทุกชุดทดลอง)

| ขั้น | ชื่อ | บทบาทโดยย่อ | บันทึกข้อมูล |
|------|------|-------------|--------------|
| Op1 | Heating | อุ่นเซ็นเซอร์ให้ถึงอุณหภูมิทำงาน | ไม่บันทึก |
| Op2 | Baseline | อ้างอิงสัญญาณเส้นฐาน | **เริ่มบันทึก** |
| Op3 | Vacuum | เตรียมสภาวะในเส้นทางก๊าซ | ต่อเนื่อง |
| Op4 | Mix air | ผสม/จัดอากาศตามลำดับระบบ | ต่อเนื่อง |
| Op5 | Measure | นำอากาศตัวอย่างเข้าห้องวัด | ต่อเนื่อง |
| Op6 | Valve return | ดูด/คืนทิศทางก๊าซตามลำดับ | ต่อเนื่อง |
| Op7 | Recovery | คืนสภาพระบบ แล้วประมวลผล ppm | สิ้นสุดรอบ |

ค่าเริ่มต้นที่คู่มือระบุ: Baseline ประมาณ 30 วินาที และ Measure ประมาณ 60 วินาที ขั้น Heating อาจใช้เวลานานกว่าขั้นอื่น (ในบางเงื่อนไขอาจถึงราว 30 นาที) ขึ้นกับค่าที่ตั้ง

### 6.4.2 การบันทึกข้อมูลดิบและการประมวลผลเบื้องต้น

ในแต่ละรอบที่บันทึก ระบบเก็บอย่างน้อย:

- สัญญาณแรงดันจากช่องเซ็นเซอร์ก๊าซผ่าน ADS1263 (อัตราสูงในระดับ ~100 Hz ตามการออกแบบระบบ)  
- อุณหภูมิ ความชื้น ความดันจาก BME280  
- เวลาสัมพัทธ์ของรอบ (`elapsed_time_sec`) และป้ายขั้นการทำงาน  

จากนั้นประมวลผลเป็นไฟล์ CSV สำหรับวิเคราะห์ โดยมีการกรองสัญญาณ (เช่น ความถี่ต่ำและค่าเฉลี่ยเคลื่อนที่) ก่อนสกัดลักษณะเด่น เพื่อลดสัญญาณรบกวนความถี่สูง

### 6.4.3 การสุ่มตัวอย่างอ้างอิงด้วย GC-FID

สำหรับรอบที่ใช้เป็นข้อมูลฝึกหรือทดสอบ ให้เก็บตัวอย่างอากาศไปวิเคราะห์ด้วย GC-FID ภายใต้เงื่อนไขที่สอดคล้องกับช่วง Measure ของรอบนั้น (จุดเวลาและตำแหน่งสุ่มตัวอย่างต้องคงที่ทั้งชุดทดลอง) ค่าความเข้มข้นจาก GC เป็นป้ายกำกับ \(y\) ของรอบนั้น [6]

เกณฑ์คุณภาพของรอบวัดที่รับเข้าชุดข้อมูล (ร่างเริ่มต้น; ปรับได้เมื่อมี SOP สุดท้าย):

- ลำดับ Op1–Op7 จบครบโดยไม่ error ของฮาร์ดแวร์  
- ไฟล์สัญญาณ Baseline และ Measure มีความยาวจริงครบตามหน้าต่างวิเคราะห์  
- มีค่า GC คู่กับรอบนั้น (สำหรับชุดที่มีป้ายกำกับ)  
- บันทึกจุดตั้งฮีตเตอร์และความเข้มข้นเป้าหมายของรอบ

## 6.5 การออกแบบการทดลองและแผนการเก็บข้อมูล

### 6.5.1 ปัจจัยและหน่วยทดลอง

หน่วยทดลองหลักคือ **หนึ่งรอบวัด Auto** ภายใต้คู่เงื่อนไข \((\text{ความเข้มข้นเป้าหมาย}, \text{อุณหภูมิฮีตเตอร์})\)

แผนการเก็บข้อมูลแบบแฟกทอเรียลในขอบเขต §6.3:

- ความเข้มข้น: 12 ระดับ (5–100 ppm ตามตาราง)  
- อุณหภูมิฮีตเตอร์: 3 ระดับ (30, 40, 50 °C)  
- การซ้ำต่อเงื่อนไข: อย่างน้อย 3 รอบ (แนะนำ 3–5) หลังระบบเสถียร  

จำนวนรอบขั้นต่ำโดยประมาณ = \(12 \times 3 \times 3 = 108\) รอบ (ยังไม่นับรอบอุ่นเครื่องหรือรอบที่ตัดทิ้ง)

### 6.5.2 การสุ่มและการควบคุมลำดับ

เพื่อลดผลของลำดับเวลาและการค้างของก๊าซในท่อ:

1. อุ่นระบบตาม Op1 จนถึงอุณหภูมิตั้งก่อนเริ่มชุดของวันนั้น  
2. สลับลำดับความเข้มข้นภายในแต่ละวันตามบล็อกที่กำหนดล่วงหน้า (ไม่เรียงจากต่ำไปสูงเพียงอย่างเดียวทั้งชุด หากทำได้)  
3. ระหว่างการเปลี่ยนความเข้มข้น ให้มีช่วงไล่ระบบ/รอสมดุลตาม SOP (**TBD**: ระยะเวลารอที่วัดจริง)  
4. บันทึกวันเวลา หมายเลขรอบ ความเข้มข้นเป้าหมาย อุณหภูมิตั้ง ค่า GC และหมายเหตุเหตุการณ์รบกวน

### 6.5.3 การแบ่งชุดฝึกและชุดทดสอบ

ใช้การแบ่งที่เคารพโครงสร้างรอบวัด เช่น **GroupKFold** โดยจัดกลุ่มตามรอบหรือตามบล็อกเงื่อนไขที่สัมพันธ์กัน เพื่อลดการรั่วไหลของข้อมูลที่เกือบซ้ำกันระหว่างพับ ชุดทดสอบสุดท้ายควรกั้นรอบที่ไม่ได้ใช้ปรับไฮเปอร์พารามิเตอร์

สัดส่วนเริ่มต้นที่แนะนำ: ประมาณ 70–80% สำหรับฝึก/ตรวจสอบไขว้ และ 20–30% สำหรับทดสอบสุดท้าย (ปรับตามจำนวนรอบจริง)

## 6.6 การสกัดลักษณะเด่น

หลักการนิยามสอดคล้อง §5.5 โดยสรุปวิธีปฏิบัติ ดังนี้

ให้ \(V_{\mathrm{bl}}\) เป็นค่าเฉลี่ยสัญญาณกรองแล้วในช่วง Baseline และให้ \(V_{\min}\), \(V_{\max}\) เป็นค่าต่ำสุดและสูงสุดในช่วง Measure ของแต่ละช่อง \(s \in \{\mathrm{ss1},\mathrm{ss2},\mathrm{ss3},\mathrm{ss4}\}\)

\[
dV_{\max,s} = V_{\max,s} - V_{\mathrm{bl},s}, \qquad
dV_{s} =
\begin{cases}
dV_{\max,s} & s \in \{\mathrm{ss3},\mathrm{ss4}\} \\
V_{\min,s} - V_{\mathrm{bl},s} & s \in \{\mathrm{ss1},\mathrm{ss2}\}
\end{cases}
\]

\[
\mathrm{slope}_{s} = \frac{V_{\max,s} - V_{\min,s}}{t_{\max,s} - t_{\min,s}}, \qquad
\mathrm{ratio}_{s} = \frac{dV_{\max,s}}{V_{\mathrm{bl},s}} \quad (V_{\mathrm{bl},s} \neq 0)
\]

นิยาม \(dV_{s}\) ข้างต้นสะท้อนท่อทำนายปัจจุบันใน `predict_methane.py` (ช่อง ss3/ss4 ใช้ \(dV_{\max}\)) ควบคู่กันไป คำนวณค่าเฉลี่ยอุณหภูมิและความชื้นในช่วง Baseline และ Measure และค่าเฉลี่ยความดันในช่วง Measure จาก BME280

หน้าต่างวิเคราะห์เวลา (วินาทีจากต้นรอบที่เริ่มบันทึก) ต้องตรงกับค่าที่บันทึกใน model bundle ตอนฝึก เช่น ค่าเริ่มต้นในโค้ดทำนายใช้ช่วง Baseline และ Measure ในรูปคู่เวลา \((t_{\mathrm{lo}}, t_{\mathrm{hi}})\) — **ค่าที่ใช้จริงทุกชุดต้องบันทึกในบันทึกทดลอง** เพราะการเปลี่ยนหน้าต่างโดยไม่ฝึกโมเดลใหม่จะทำให้การทำนายคลาดเคลื่อน

เวกเตอร์ลักษณะเด่นที่ใช้ทำนายคือเซ็ตย่อย \(\mathbf{x}\) ที่เลือกไว้ตอนฝึกเท่านั้น ไม่จำเป็นต้องใช้ทุกตัวที่คำนวณได้ข้างต้น

## 6.7 การสร้างแบบจำลองและการทำนาย

### 6.7.1 แบบจำลองหลัก

แบบจำลองหลักที่นำขึ้นเครื่องคือ **Linear Regression** ที่ฝึกนอก Raspberry Pi แล้วบันทึกเป็นไฟล์โมเดล (`joblib`) พร้อมรายการลักษณะเด่นที่เลือกและหน้าต่างวิเคราะห์ หลังจบรอบวัด ระบบเรียกฟังก์ชันทำนายเพื่อแสดงค่า ppm บน GUI ตาม

\[
\hat{y} = \hat{\beta}_0 + \sum_{j=1}^{p} \hat{\beta}_j x_j
\]

เมื่อ \(\{x_j\}_{j=1}^{p}\) คือลักษณะเด่นในรายการ `selected_features` ของ model bundle และ \(\hat{\boldsymbol{\beta}}\) ได้จากกำลังสองน้อยที่สุดบนชุดฝึก (ดู §5.6.2)

เหตุผลที่เลือกแบบเชิงเส้นเป็นจุดตั้งต้น: ตีความได้ ภาระคำนวณต่ำบน Raspberry Pi และสอดคล้องกับเป้าหมายวิทยานิพนธ์ที่เน้นระบบที่ใช้งานได้จริงภายใต้ขอบเขตที่กำหนด หากผลการประเมินชี้ว่าความคลาดเคลื่อนยังสูงเกินไปในบางช่วงความเข้มข้น อาจเปรียบเทียบแบบจำลองทางเลือก (เช่น แบบมีอันตรกิริยา ต้นไม้ หรือการแปลงลักษณะเด่น) เป็นการวิเคราะห์เสริม โดยไม่จำเป็นต้องเปลี่ยนฮาร์ดแวร์ [10], [27], [29]

### 6.7.2 การคัดเลือกลักษณะเด่น

ขั้นตอนที่ทำได้ซ้ำและรายงานได้:

1. คำนวณสหสัมพันธ์ของแต่ละลักษณะเด่นกับความเข้มข้นอ้างอิงจาก GC เช่น สหสัมพันธ์เพียร์สัน
   \[
   r_{x y} = \frac{\sum_{i}(x_i-\bar{x})(y_i-\bar{y})}{\sqrt{\sum_{i}(x_i-\bar{x})^2}\,\sqrt{\sum_{i}(y_i-\bar{y})^2}}
   \]
2. คัดชุดตั้งต้นตามเกณฑ์ความสัมพันธ์และความซ้ำซ้อนระหว่างตัวแปร  
3. ยืนยันด้วยการตรวจสอบไขว้แบบกลุ่มว่าชุดลักษณะเด่นที่เลือกไม่ทำให้คะแนนบนชุดทดสอบแย่ลงอย่างมีนัย

รายการลักษณะเด่นสุดท้ายต้องตรงกับที่บันทึกใน model bundle ที่ deploy

### 6.7.3 ตัวชี้วัดการประเมิน

ประเมินบนชุดทดสอบ (และรายงานค่าตรวจสอบไขว้แยกต่างหาก) ด้วยอย่างน้อย RMSE, MAE และ \(R^2\) ตามนิยามใน §5.6.3:

\[
\mathrm{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}, \quad
\mathrm{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|, \quad
R^2 = 1 - \frac{\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}{\sum_{i=1}^{n}(y_i-\bar{y})^2}
\]

| ตัวชี้วัด | ความหมายในงานนี้ |
|----------|------------------|
| RMSE | รากของค่าเฉลี่ยกำลังสองของความคลาดเคลื่อน (ppm) |
| MAE | ค่าเฉลี่ยของค่าสัมบูรณ์ของความคลาดเคลื่อน (ppm) |
| \(R^2\) | สัดส่วนความแปรปรวนของค่าอ้างอิงที่แบบจำลองอธิบายได้บนชุดที่ประเมิน |

นอกจากนี้ควรรายงานความคลาดเคลื่อนแยกตามช่วงความเข้มข้นและตามอุณหภูมิฮีตเตอร์ เพื่อระบุเงื่อนไขที่ระบบอ่อนแอ และอาจรายงานส่วนค้าง \(e_i = y_i - \hat{y}_i\) เป็นกราฟเทียบ \(\hat{y}_i\) หรือเทียบระดับ ppm

### 6.7.4 หมายเหตุการแปลงเป็นฟลักซ์ (นอกขอบเขตหลัก)

ถ้าในอนาคตต้องการรายงานฟลักซ์จากชุด chamber ที่ทราบ \(V\), \(A\) ให้ใช้ความสัมพันธ์ใน §5.3.3

\[
F = \frac{\mathrm{d}C}{\mathrm{d}t} \cdot \frac{V}{A} \cdot \frac{P M}{R T}
\]

โดย \(\mathrm{d}C/\mathrm{d}t\) มาจากหลายจุดความเข้มข้นตามเวลา (จาก GC หรือจาก eNose ที่สอบเทียบแล้ว) **ขั้นตอนนี้ไม่ใช่เอาต์พุตตรงของโมเดล Linear Regression ในงานปัจจุบัน** ซึ่งให้เพียง \(\hat{y}\) เป็น ppm ต่อรอบวัด

## 6.8 การวิเคราะห์ข้อมูลและการรายงาน

1. **สรุปชุดข้อมูล:** จำนวนรอบทั้งหมด รอบที่ตัดทิ้ง สาเหตุการตัด และตารางเงื่อนไขที่ครบ  
2. **คุณภาพสัญญาณ:** ตัวอย่างเส้นเวลา Baseline–Measure ของแต่ละช่อง และสถิติลักษณะเด่น  
3. **ผลการถดถอย:** ตารางเมตริกรวม กราฟค่าทำนายเทียบค่า GC และส่วนค้าง (residuals)  
4. **การวิเคราะห์เงื่อนไข:** ความคลาดเคลื่อนตามระดับ ppm และตามอุณหภูมิตั้ง  
5. **ข้อจำกัด:** ช่วงที่ใช้ได้ เงื่อนไขที่นอกขอบเขต และสิ่งที่ต้องทำก่อนใช้ในนาจริง  

การตีความผลต้องคงเส้นแบ่งว่าความสอดคล้องของ ppm ที่จุดสุ่มตัวอย่างหนึ่ง **ไม่เท่ากับ** การรับรองฟลักซ์ตลอดฤดูปลูก [6], [7]

## 6.10 สรุปวิธีวิจัย

วิธีวิจัยนี้ประกอบด้วยระบบ eNose บน Raspberry Pi ที่ใช้อาเรย์ TGS2612 ร่วมกับ BME280 เก็บสัญญาณตามลำดับ Baseline–Measure แล้วประมาณความเข้มข้น CH₄ เป็น ppm ด้วยแบบจำลองถดถอยที่สอบเทียบกับ GC-FID ภายใต้ตารางความเข้มข้น 5–100 ppm และอุณหภูมิฮีตเตอร์ 30–50 °C ระบบถูกวางเป็นเครื่องมือเสริมสำหรับการประมาณความเข้มข้นภายใต้ขอบเขตที่ฝึก ไม่ใช่การทดแทน chamber–GC สำหรับรายงานฟลักซ์มาตรฐานของนาข้าว
